# Interactive Dance

TouchDesigner tools for interactive dance projects. The first is a simple toolkit for an interactive dance workshop. Participants choreograph movement and build interactive performances; the toolkit does the technical work of connecting music, sensors and visuals.

The finished toolkit will combine:

- music with MIDI-programmed events
- four flexible visual layers
- MIDI-triggered visual actions
- custom movement sensors (serial)
- MediaPipe camera-based body tracking
- a simple table that connects inputs to visual actions

It is built one small step at a time. **Status: Task 01 (synchronized audio and MIDI playback) is done.** Visual layers come next.

## Requirements

- [TouchDesigner](https://derivative.ca/download) 2025.32280 or later (the free Non-Commercial licence is enough)
- Tested on Windows 11 so far

## Getting started

1. Clone or download this repository.
2. Open `TouchDesigner/DanceWorkshop.toe` in TouchDesigner.
3. Go into `project1`, click the **transport** component, and press **P** to open its parameters.
4. On the **Transport** page, turn **Play** on. You will hear the test track: a click every second and a tone at 5, 10, 15 and 20 seconds.

## The transport

`project1/transport` plays a music file and a MIDI file together on one shared clock.

| Control | What it does |
|---|---|
| **Audio File** | The music (WAV or MP3) |
| **MIDI File** | A Standard MIDI File (`.mid`) with the events for that music |
| **Play** | On plays, off pauses. Audio and MIDI always move together |
| **Reset** | Back to 0 seconds |
| **Seek To** + **Seek** | Jump to a position in seconds |
| **Position** / **Length** | Current position and track length (read-only) |

When the playback passes a MIDI Note On, its note number (0-127) appears in `transport/notes_now` for that frame, and in `transport/note_log` as a running history. To see them, go inside the transport (press **I**) and turn on the viewer of `note_log`.

Behaviour:

- Notes that start at the same moment (chords) are all reported.
- Nothing fires while paused, so pausing never repeats a note.
- Reset and Seek do not fire the notes they jump over, or a note they land in the middle of.
- Velocity, MIDI channel and Note Off are ignored for now.

### How it works

The transport has its own timeline (a Time COMP in `transport/local/time`), which is the only clock. The Audio File In CHOP is *Locked to Timeline*, so the audio always plays from that clock's position. The MIDI In CHOP reads the whole MIDI file as a fixed clip with one channel per note, so it has no timer of its own. Each frame, a short script (`note_events`) looks at the part of that clip between the previous and the current clock position and reports any note that switched on.

Because the MIDI file is held as a clip, it is always possible to ask which notes come before any position. Later tasks use this to restore the visual state when you seek.

### Known limitations

- Notes are reported on the frame the clock reaches them, up to one frame late (17 ms at 60 fps). The exact note time is in `notes_now`.
- The audio you hear lags the note events by the audio output buffer (about 0.15 s in TouchDesigner, plus the operating system, plus remote desktop if you use it). A latency setting can be added once it is measured on the performance setup.
- If TouchDesigner drops many frames, the audio follows the clock and may skip.

## Testing

`project1/test_t01` runs the Task 01 checks automatically over 30 seconds: play, pause at 8 s, resume, seek to 12 s, reset, chords at 20 s, and seeking into a held note. Open the Textport (**Alt+T**) and run:

```python
op('/project1/test_t01/sync_test').module.Start()
```

Results appear in `test_t01/results` and `transport/note_log`.

The test media in `media/test/` (a 30-second WAV and a MIDI file with notes 60, 62, 64 and the chord 65 + 67 at 5, 10, 15 and 20 seconds) is generated by `tools/make_test_media.py`, using only the Python standard library:

```
python tools/make_test_media.py
```
